候选市场评分表
更新：2026年8月27日

这张表不是市场规模的占卜。它只回答一件更实际的事：一个人能不能用合规的数据源，在三十天内做出英文自助购买的 API，并把它维持下去。

计分办法
刚需与重复调用，满分三十。看开发者会不会把数据接入销售、供应商研究、投标监控或研究工具，而不是只试一次。
来源与授权，满分二十五。看官方来源是否允许预期用途，接口是否稳定，是否能保留出处。
产品增值，满分二十。原始数据若已足够好，别人没有理由多付一层费用；要看清洗、统一字段、时间线、监控和检索能否省下真实工时。
英文自助市场，满分十五。看有没有清楚的国际买家、英文文档和无需线下销售的购买路径。
运维负担，满分十。看令牌、抓取频率、变更风险、成本和客服是否能由一个人守住。

准入线
总分低于七十五分，不立项。
来源的授权或可持续性低于十八分，不立项，即使总分看起来很高。
没有在 RapidAPI 或独立落地页拿到连续十四天的真实搜索、订阅或试用信号，也不扩成第二个独立 API。

这几分从哪里来
TED 的官方 Search API 明说可供商业组织把公告检索、分析和再利用接入自己的平台，匿名访问也可以先做验证。它面对的是跨国采购和供应商研究，英语用户能一眼看懂用途。它的短板是数据模型复杂、国家差异大，所以没有给满分。

美国联邦合同在 2025 财年约为 7927.7 亿美元，SAM 生态约有 78 万活跃注册实体、每月约 2 万个新机会。SAM.gov Opportunities 与 USAspending 都有官方 API，英文自助市场也最大。GovTribe、GovSpend 已经把原始搜索做得很成熟，所以第二个产品不能是 SAM 包装层；它必须复用当前项目刚完成的变更监控、供应商档案、买方洞察和机器可读行动状态，并加入 NAICS/PSC、set-aside、现任供应商与潜在续约信号。

中国的绝对需求很大：2024 年政府采购规模约 3.375 万亿元人民币。但政府采购接口主要面向地方财政部门申请，主流企业数据 API 又有内部使用和禁止转售约束；跨境交付、本地平台资质与数据合规会把单人自助 API 的优势吃掉。没有逐字段书面授权和本地合作方之前不立项。

美国上市公司数据虽然有免费的 SEC API，但通用事件信号竞争拥挤；一旦加入实时行情，还会进入交易所再分发许可与费用体系。它适合以后作为“上市政府承包商合同暴露”模块接入美国采购产品，而不是单独做第二个泛美股 API。

日本补助金方向并非没有需求，问题在于当前已验证的上游端点返回 404。把空缺包装成产品，后来一定要补洞。这个项目先不碰。

“泛爬虫潜客库”看着容易复制，实际上要逐站处理条款、robots、字段质量和投诉。它不是 API 生意，更像把风险拆成许多小账单。

结论
第二个独立 API 更新为 US Federal Contractor Recompete & Supplier-Fit Signals API。第一版不卖原始搜索，只卖公告修订与截止日变化、供应商能力和 NAICS/PSC/set-aside 匹配、买方采购偏好、现任供应商和潜在 recompete，以及 `review_now / monitor / low_fit / deadline_risk` 行动状态。EU Tender Signals 保留为第三候选。

启动门槛
先让升级后的 JP Business Signals 跑满十四天。观察公开演示转化、RapidAPI 非本人调用、最常用路径、错误率和是否有人进入付费套餐。十四天后，只要有十次以上非本人测试调用，且官方源、Railway 成本和变更历史没有异常，就启动美国产品的一周数据可行性验证；若没有，先根据真实搜索词修正公开演示和产品定位，而不是继续盲目横向复制。
